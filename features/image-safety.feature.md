# Feature: 表示数式を安全に遅延準備する

Formula for Pi の利用者として
数式を使わない会話を重くしたくない
読めない画像や無制限の一時保存を避けたい

## Scenario: 画像処理に固定上限がある

- Given pi-formula の画像処理設定を読む
- When 固定上限を確認する
- Then 入力文字数、画像列数・行数、一時保存件数・バイト数が有限の正数である

## Scenario: 上限を超えた表示数式だけを文字へ戻す

- Given 画像経路で数式を描ける Pi がある
- When 上限を超えた表示数式と正しい表示数式を変換する
- Then 上限を超えた数式は残り、正しい数式だけが画像になる

## Scenario: 小さくなりすぎる表示数式だけを文字へ戻す

- Given 画像経路で数式を描ける Pi がある
- When 基準の半分より小さくなる表示数式と正しい表示数式を変換する
- Then 小さくなりすぎる数式は残り、正しい数式だけが画像になる

## Scenario: テーマ色と表示幅を一時保存の識別に含める

- Given 画像経路で数式を描ける Pi がある
- When 同じ表示数式を異なるテーマ色と表示幅で変換する
- Then テーマ色と表示幅ごとに異なる画像になる

## Scenario: 正確な RGB がない場合は文字へ戻す

- Given 正確な RGB を返さない画像経路の Pi がある
- When 表示数式を変換する
- Then RGB を得られない数式は原文のまま残る

## Scenario: 失敗結果を一時保存する

- Given 画像経路で数式を描ける Pi がある
- When 同じ不正な表示数式を二回変換する
- Then 二回目の失敗結果は5ミリ秒未満で返る

## Scenario: 数式画像をメモリ内だけで作る

- Given 画像経路で数式を描ける Pi がある
- When 外部作用を監視しながら表示数式を変換する
- Then SVGとPNGの保存、ネットワーク、ブラウザ、子プロセスを使わない

## Scenario: 最初の表示数式まで画像処理を準備しない

- Given pi-formula を新しい Node.js プロセスで読み込む
- When 表示数式を初めて変換する
- Then MathJaxとResvgは最初の表示数式で初めて準備される

## Scenario: 表示数式を時間上限内で処理する

- Given 画像経路で数式を描ける Pi がある
- When 初回、次の異なる数式、一時保存済み数式を計測する
- Then 初回は1秒未満、次は200ミリ秒未満、一時保存済みは5ミリ秒未満である
