# Feature: 独立した検証セッションで表示数式を検証する

pi-formula の worker として
利用者の画面と作業を妨げずに
表示数式の実表示を履歴全体で回帰検証したい

## Scenario: 目視確認用のキャプチャを取得する

- Given 実行可能な実表示検証の試験環境がある
- When 実表示検証の interface を実行する
- Then 目視確認用のキャプチャを返す

## Scenario: 応答不一致をキャプチャ前に拒否する

- Given 実行可能な実表示検証の試験環境がある
- And 応答がコーパスと異なる
- When 実表示検証の interface を実行する
- Then 応答確認 stage の失敗を返す

## Scenario: 描き直し前後のキャプチャを残す

- Given 実行可能な実表示検証の試験環境がある
- And 100 列へ描き直す
- When 実表示検証の interface を実行する
- Then 変更前後のキャプチャを返す

## Scenario: Issue 21 の再現コーパスを使う

- Given Issue 21 の再現コーパスがある
- Then Issue 21 の最後の表示数式がコーパスに含まれる

## Scenario: Issue 26 の再現原文を使う

- Given Issue 26 の再現コーパスがある
- Then 追加マクロを含む3つの表示数式を組版できる

## Scenario: Issue 48 の Grover コーパスを組版する

- Given Issue 48 の Grover コーパスがある
- Then bra と braket を含む表示数式を組版できる

## Scenario: braket の直後の項を分ける

- Given braket の直後に ket が続く表示数式がある
- Then braket と直後の ket は別の項へ展開される

## Scenario: bra の定義を保つ

- Given bra を使う表示数式がある
- Then bra は山括弧と縦線へ展開される

## Scenario: ket の定義を保つ

- Given ket を使う表示数式がある
- Then ket は縦線と山括弧へ展開される

## Scenario: Issue 52 の幅掃引コーパスを組版する

- Given Issue 52 の幅掃引コーパスがある
- Then 項数3から15までの7つの表示数式を組版できる

## Scenario: 検証ハーネスの追加マクロを qni-cli と揃える

- Given 検証ハーネスと書式だけが異なる qni-cli の追加マクロ定義がある
- Then 検証ハーネスの追加マクロは qni-cli と一致する

## Scenario: qni-cli の追加マクロ変更を検出する

- Given 検証ハーネスと値が異なる qni-cli の追加マクロ定義がある
- Then 検証ハーネスは qni-cli の定義差分を検出する

## Scenario: qni-cli の追加マクロ定義が見つからない理由を示す

- Given 追加マクロ定義のない qni-cli ソースがある
- When qni-cli の追加マクロ定義を読み取る
- Then 読み取り失敗は対象ファイルを示す

## Scenario: 組版できない表示数式だけをテキスト経路へ戻す

- Given 組版できる式と組版できない式を含むコーパスがある
- When 表示数式の画像行数を含む出力高を計画する
- Then 組版失敗を数えて残りの表示数式の計画を続ける

## Scenario: 組版できない表示数式を検証結果で知らせる

- Given 組版できる式と組版できない式を含むコーパスがある
- When 実表示検証の表示計画境界を実行する
- Then verify-display は組版に失敗した表示数式の数を出す

## Scenario: すべての表示数式をテキスト経路へ戻す

- Given 組版できない表示数式だけのコーパスがある
- When 実表示検証の表示計画境界を実行する
- Then 画像行がなくても組版失敗を報告して計画を続ける

## Scenario: テキスト経路の表示計画では画像を組版しない

- Given 組版できない表示数式だけのコーパスがある
- When テキスト経路の表示計画境界を実行する
- Then 表示計画は画像の組版結果を含まない

## Scenario: リフロー後の履歴全体が収まる寸法を計画する

- Given 100 列へのリフローで折り返しが増えるコーパスがある
- When 100 列とテキスト経路の表示計画境界を実行する
- Then 表示計画は両方の描画が収まる寸法を返す

## Scenario: リフロー後だけ収まらない理由を報告する

- Given 100 列へのリフロー後だけ上限を超えるコーパスがある
- When 100 列とテキスト経路の表示計画境界を実行する
- Then 表示計画はリフロー幅と必要な高さを示して描画前に拒否する

## Scenario: Markdown の折り返しを表示計画へ含める

- Given 全角文字と空白を含む Markdown 表のコーパスがある
- When 100 列とテキスト経路の表示計画境界を実行する
- Then 表示計画は Markdown 表の折り返しを含む

## Scenario: リフロー後に読めない縮尺になる表示数式を数える

- Given 100 列では読めない縮尺になる表示数式がある
- When 100 列と画像経路の表示計画境界を実行する
- Then 表示計画は読めない縮尺を組版失敗として報告する

## Scenario: 画像転送行を表示計画へ含める

- Given 60 個の短い表示数式を含むコーパスがある
- When 実表示検証の表示計画境界を実行する
- Then 表示計画は画像転送行を含む高さ超過を報告する

## Scenario: 表示計画の実際の失敗理由を保つ

- Given 読み取れないコーパスのパスがある
- When 実表示検証の表示計画境界を実行する
- Then verify-display は高さ超過と決めつけず planner の理由を出す

## Scenario: 組版失敗した長い表示数式を一度だけ数える

- Given 文字数上限を超える表示数式を含む収容可能なコーパスがある
- When 表示数式の画像行数を含む出力高を計画する
- Then テキスト経路の行数を二重に数えず計画を続ける

## Scenario: 短いが高い表示数式を事前に拒否する

- Given 16000px を超える高い表示数式を含む短いコーパスがある
- When 実表示検証の表示計画境界を実行する
- Then 全履歴が収まらないコーパスは描画前に拒否される
