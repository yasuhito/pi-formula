# 表示数式の実表示検証

`scripts/verify-display` は、Ghostty 上の Pi に表示数式を描画させ、色帯や黒帯をピクセルで検出するローカル専用ハーネスである。保存済み Markdown を回帰検証する**コーパスモード**と、自由なプロンプトから未知の異常を探す**探索モード**がある。表示が正常でも道具が期待どおり働かなかった状態は、独立した[セッション記録のツール失敗検査](verify-session-record.md)で検出する。

## 実行

cage、wlr-randr、Ghostty、grim、jq、Node.js、Pi が必要になる。利用者の compositor には依存しない。

コーパスモードは、従来どおりコーパスのパスを渡す。

```sh
scripts/verify-display docs/agents/verify-corpus/issue-21.md
```

探索モードは `--prompt` に自由なプロンプトを渡す。安全な接頭辞を付けた入力を、検証補助拡張が Pi の公開 `input` event で元の文字列へ戻すため、先頭が `-` や `@` でも CLI のオプションやファイル入力にはならない。検証補助拡張は、公開 `message_update` の未完了本文から完全な表示数式を見つける。公開 Markdown transformer がその式を含む未完了本文をテキスト経路へ実際に渡したことを記録してから、次の更新または確定処理で応答を一時停止する。ハーネスはまず、`input` event で応答開始を止め、対象式がない画面を2枚の一致で確定して基準キャプチャにする。対象式の transformer marker を受け取った後は2秒待ち、Pi の描画と compositor 反映に機会を与えてから、検証セッション内の Pi process を一時停止して進捗表示のアニメーションも止める。2秒間隔の2枚が一致し、かつ基準キャプチャから画面が変わった場合だけ描画が安定したと判定する。その画面をピクセル判定してから Pi process と応答を再開する。続いて、公開 Markdown transformer の前後で対象式だけに印を付け、対象の assistant message の確定本文でも同じ式が表示数式として認識され、pi-formula によって Kitty 画像へ置き換わったことを確認する。tool を呼ぶ場合は公開 `tool_call` event で実行を止め、対象式の確定画面を2枚の一致で撮影・判定してから再開する。後続の tool result や別の assistant message は、この撮影と成功結果を上書きしない。tool を呼ばず応答が終わる場合は、対象式から応答末尾までを各文字最大2セルで折り返し、Markdown の行追加に備えて行数をさらに2倍して保守的に数え、UI用の余白を引いた実端末行数内に収まる場合だけ完了直後の画面を撮影・判定する。同じ message 内の長い後続本文で対象式が画面外になり得る場合は exit 2 にする。原文へ戻った式や、確定時に通常のコードになった式も exit 2 にする。応答全体の内容やプロンプトとの一致は判定しない。

```sh
scripts/verify-display --prompt '表示数式を使ってフーリエ変換を説明してください。'
```

探索モードへ tool 用の拡張を追加する場合は、`--extension` を繰り返し渡し、使用を許可するツール名だけを `--tools` のカンマ区切りで渡す。拡張の自動探索と、指定していないツールは無効のままにする。追加する拡張は Markdown transformer を登録せず、必要な追加マクロを pi-formula の公開 `registerFormula(pi, macros)` へ渡すものに限る。これにより、ストリーミング中のテキスト経路と確定後の画像経路を pi-formula 一つで描画する。

現在の qni-cli 0.1.0 にある `dist/qni-math/index.js` は、`qni` tool と独自の Markdown transformer を一緒に登録するため互換性がない。ハーネスはこの entry point を拒否する。qni-cli と併用するには、qni-cli 側へ tool の登録と `registerFormula` による追加マクロ登録だけを行う互換 entry point を追加する必要がある。

この依存作業が終わるまで Issue #49 の「qni-cli など他の拡張と組み合わせた実利用の再現」は未達であり、Issue #49 を閉じない。対応 PR は `Closes #49` ではなく `Refs #49` とし、qni-cli 側の follow-up issue を依存先として示す。その他の受け入れ基準（自由なプロンプト、終了コード、応答保存、コーパスモード非退行、同一セッションでの未完了時と確定後の撮影・判定、利用方法、`npm run check`）は、このリポジトリで検証する。

異常を回帰検証へ昇格させる場合は、`--save-response` で実表示検査の対象式を含む確定 assistant message をコーパスへ保存する。応答末尾の CRLF、LF、CR は除去し、それ以外は一字一句そのまま保存する。tool の後に別の assistant message が続いても、最後の message ではなく検査対象の message を保存する。保存はピクセル判定より先に行うため、水平帯を検出して exit 1 になった応答も残る。

```sh
scripts/verify-display \
  --prompt '表示数式を使ってフーリエ変換を説明してください。' \
  --save-response docs/agents/verify-corpus/fourier-transform.md
```

異常がなければ0、水平帯を検出すると1、準備・描画・キャプチャに失敗すると2で終了する。終了コード1を返すのはピクセル判定が帯を検出した場合だけとする。それ以前のコマンド失敗と判定器のtimeout・実行失敗は、元の終了コードと実コマンド名をstderrへ示して2に正規化する。セッション待機では未完了だけを無言の1として扱い、JSONL解析失敗や検査timeoutは直ちに2とする。ビルドの標準出力と標準エラーは原因調査のため保持する。検出時は次のように座標とRGBを表示する。

```text
異常な水平帯を 1 件検出しました
- x=120..1780, y=940..1012, rgb=210,0,170
```

確定後に撮れた画面は必ず `$XDG_STATE_HOME/pi-formula/verify-display-capture.png`（既定は `~/.local/state/pi-formula/verify-display-capture.png`）へ残し、その場所を標準出力へ示す。探索モードは未完了時の画面も同じ場所の `verify-display-capture-streaming.png` へ残す。保存先はそれぞれ `PI_FORMULA_VERIFY_CAPTURE` と `PI_FORMULA_VERIFY_STREAM_CAPTURE` で変更できる。表示が正しいかどうかの最終的な判断は、これらのキャプチャを人と Agent が目で見て行う。両方の判定器が実行でき、どちらかで帯を検出した場合は exit 1 にする。どちらかの判定器を実行できなければ、帯の有無より優先して exit 2 にする。

```sh
PI_FORMULA_VERIFY_CAPTURE=/tmp/issue-21.png \
  scripts/verify-display docs/agents/verify-corpus/issue-21.md
```

どちらのモードも、既定ではプロジェクトの Pi 設定にあるモデルを使う。安価なモデルを指定する場合は `PI_FORMULA_VERIFY_MODEL` を使う。拡張は利用者・project の設定から探索しない。`--no-extensions` と `--extension` を併用し、実行中の checkout にある `src/extension.ts` と検証補助拡張を読み込む。コーパスモードは追加の拡張を受け付けず、すべてのツールを無効にする。探索モードも、明示した互換拡張とツールだけを有効にする。セッション記録は終了時に削除するため、tool の成否を後から検査できない。詳しい制約は[セッション記録のツール失敗検査](verify-session-record.md)を参照する。

pi-formula の設定は一時 `XDG_CONFIG_HOME` へ隔離し、利用者マクロも空に固定する。検証専用の追加マクロは qni-cli の `ket`、`bra`、`braket` と同じ定義を使う。`braket` は `\braket{A|B}` 全体を一つの引数として受け取り、直後の項を取り込まない。CI は qni-cli の現在の `src/qni-math/typesetter.ts` を TypeScript の構文として読み、追加マクロの名前、展開値、引数数を照合する。ソースの書式だけが変わっても受理し、追加マクロが変わった場合は同期漏れとして失敗する。現在の checkout の公開 API で試験用 PNG を作り、8 byte の PNG 署名が完全に一致したことを補助拡張が記録する。保存済みの `path: "text"`、PNG 問い合わせ失敗、その他の理由で画像経路を選べない場合は exit 2 とし、キャプチャへ進まない。

```sh
PI_FORMULA_VERIFY_MODEL=openrouter/z-ai/glm-5.3-flash \
  scripts/verify-display docs/agents/verify-corpus/issue-21.md
```

## 安全性

ハーネスは利用者の画面をいっさい使わない。`WAYLAND_DISPLAY` と `DISPLAY` を外し、`WLR_BACKENDS=headless` の `cage` を専用の process group で起動して、その中だけで Ghostty を描画しキャプチャする。利用者の compositor から独立しているため、フォーカスもワークスペースも奪わず、画面ロック中でも実行できる。ロック状態の検査は不要になった。

`cage` の headless 出力は既定で 1280x720 なので、検証セッションの中で `wlr-randr --custom-mode` を使い 1920 x 計画高へ広げる。広げてから、そのセッションの `WAYLAND_DISPLAY` をファイル経由で外へ伝える。ハーネスはこの窓口へ向けてのみ `grim` を実行する。利用者の画面を撮ることは構造的に起こらない。`cage` は kiosk compositor で唯一のクライアントを出力全体へ広げるため、ウィンドウ矩形の切り出しも要らない。キャプチャの寸法が 1920 x 計画高であることを確認してから応答を待つ。

検証セッションが起動しない場合は `cage` のログ末尾を添えて exit 2 で停止する。無言で待ち続けることはしない。

すべての外部処理には時間上限がある。通常の外部処理は8秒、ビルドは120秒、最大画像のピクセル判定は30秒とする。`grim` が8秒以内に応答しない場合も打ち切り、キャプチャ不能としてexit 2にする。描画完了の確認には、対象式前、未完了時、確定後にそれぞれ実時間で最大30秒の再試行予算を使い、2秒間隔で撮り直す。Ghostty の寿命は、コーパスモードでは240秒、探索モードでは600秒とする。探索モードの600秒は、起動30秒、画像経路15秒、対象式前の準備30秒、対象式前の撮影ゲート60秒、対象式前の描画30秒、表示数式待ち30秒、撮影ゲート60秒、未完了描画30秒、対象式の確定撮影ゲート60秒、確定描画30秒、応答完了150秒、2回の判定各30秒、通常コマンド8秒の合計593秒より長く、各期限と余裕を含む。

`EXIT`、`INT`、`TERM`、`HUP`のtrapは検証セッションの process group を停止する。`cage` を止めれば、その中の Ghostty も Pi も出力も一緒に消えるため、個別の後片付けは要らない。

## 履歴全体

コーパスモードでは、コーパスを現在の typesetter で事前に組版し、各表示数式の実際の画像行数を求める。表示数式ごとに組版失敗を捕捉し、失敗した式は実行時と同じくテキスト経路へ戻して、残りの式の計画を続ける。テキスト経路へ戻る式の原文行は Markdown の行数・折り返し量に含まれるため、重ねて加算しない。組版に失敗した表示数式の数は `verify-display` の出力へ示す。Markdown の行数・折り返し量、入力と応答の2回分の画像行数、Pi の画面部品を含む保守的な余白から、8000〜16000 px の縦長 headless 出力を選ぶ。短い LaTeX でも画像が高ければ必要高へ加算する。16000 px に収まらないコーパスは、ビューポートだけを撮らず描画前に拒否する。表示計画が失敗した場合は、高さ超過と決めつけず planner が示した実際の理由を保って exit 2 にする。探索モードは応答を事前に計画できないため、上限の16000 pxを使う。

受理した入力はスクロールや画像結合を使わず、`grim` の 1 枚で履歴全体を取得する。PNGのIHDRが計画した出力寸法に一致しなければ、履歴欠落としてexit 2にする。コーパスモードだけ、キャプチャ前に session JSONL の最後の完了した assistant message から text content を取り出す。コーパスと応答の末尾にある CRLF、LF、CR を除去した後、残りを一字一句比較する。コードフェンス、Unicode 化、前置き、欠落を含む不一致は exit 2 とし、キャプチャへ進まない。探索モードはこの一致検証を行わず、モデルが生成した応答をそのまま描画する。探索モードでは、応答開始前に対象式がない安定画面を基準として保存する。完全な表示数式を含む未完了本文がストリーミング用 Markdown transformer のテキスト経路へ渡ったことを確認した後、2秒間は Pi と compositor を動かして描画機会を確保する。それから応答と Pi process を止め、進捗表示を含む2秒間隔の2枚が一致し、かつ基準キャプチャから変わるまで撮り直して、安定した1枚を判定する。ゲート解除後は、対象式を見つけた assistant message の確定本文で同じ式を表示数式として再認識し、その式を挟む印の内側に Kitty 画像転送があることを後段の公開 Markdown transformer で確認する。tool を呼ぶ場合は公開 `tool_call` event で実行を止め、Pi と compositor の描画機会を確保してから対象式の確定画面を撮影・判定する。撮影が終わるまで tool result と後続 assistant message は表示されないため、16000pxを超える後続出力があっても対象式は画面外へ流れない。tool を呼ばない場合は、確定 transformer の出力で対象式から message 末尾までを数える。Kitty 転送とANSI制御列を除き、各文字を最大2セルとして端末幅で折り返し、Markdown 描画による行追加に備えて2倍した上限行数に、実端末行数の10%（最低20行）をUI用として加える。この合計が端末行数を超える場合は、同じ message の後続本文で対象式が画面外になり得るため exit 2 にする。収まる場合だけ、対象 message でセッションが完了した直後に同じ撮影・判定を行う。対象式の確定キャプチャは後続 message の完了後に撮り直さず、対象 message の成功結果とともに保持する。完全な表示数式を含む未完了本文を観測できない応答、対象式が原文へ戻る応答、対象式が通常のコードへ確定する応答は exit 2 にする。

応答が完了していてもGhosttyがまだ描き終えていないことがあるため、帯の判定より前に描画完了を確認する。判定は内容を解釈せず、次の3条件だけで決める。専用の端末背景がキャプチャの1%以上を占めること（端末が写っている）、背景以外の描画が0.1%以上あること（何かが描かれている）、そして前回のキャプチャとピクセルが完全に一致すること（描画が安定した）である。端末背景には素の背景色に加えてPiの引用ブロック背景も渡す。表示数式は引用ブロックの中へ描かれるため、ブロック背景を背景として数えないと描画量を正しく測れない。

この判定は「テキストか表示数式か」を区別しない。実際のキャプチャでは日本語テキストと数式画像がピクセル特徴で分離できず、閾値による同定はフォントサイズ・出力幅・コーパスの内容に依存して壊れるためである。表示数式そのものの正しさは、末尾改行を除去したセッション記録とコーパスの一字一句照合と、後段の帯検出が受け持つ。検証セッションは利用者の画面から独立しているため、ロック画面が写り込むことはない。

条件を満たすまで2秒間隔でキャプチャを撮り直す。期限は実時間で30秒とし、超過した場合は帯の判定へ進まずexit 2にする。キャプチャのPNGが読めないなど検査自体の実行失敗は再試行せず、直ちにexit 2にする。保存先を指定したキャプチャは、描画完了を確認できたものだけを残す。

この方式は GPU の最大テクスチャ寸法以下に限られる。長大な会話履歴一般を撮る道具ではなく、指定コーパスを一度だけ回帰検証するためのものとする。

## 判定

`scripts/detect-display-bands.js` は標準のcompression methodとfilter methodを使う8-bit RGB/RGBAの非インターレースPNGを読む。scanline の展開長が画像寸法と厳密に一致しない PNG は破損として拒否する。画素数の上限は 1920×16000 とする。

ハーネスは専用の Pi theme と Ghostty の背景色・本文色を使う。判定器へ背景色、本文色、theme の全 UI 色を明示し、それらを候補から除く。このため、本文色の長い分数線、コード、URL、金額、シェル変数、非数式 UI を水平帯と誤認しない。専用 palette と量子化誤差2以内で一致しない ID 色や黒色について、2px 以上の同色成分を走査する。同じ行で16px 以下の字形の隙間を挟む同色成分をまとめ、幅48px 以上かつ40%以上が同色の領域が垂直に3行以上連続する場合を水平帯とする。離れた本文行は結合しない。画面幅ではなく帯自体の幅を使うため、幅384px未満の短い表示数式も判定できる。画面上下 1% の compositor 部品は対象外にする。

画素色は 24-bit 整数で扱い、背景色は固定長 histogram の一走査で求める。判定時間は画素数に比例する。横方向に色が変わり続ける上限寸法 1920×16000 の合成 PNG を、実処理と同じ30秒の上限で判定する回帰試験を置く。

この判定は決定的な一次判定であり、数式の組版品質や内容の正しさまでは判定しない。
